# 코스피·코스닥 상장사 분기 재무·인력 데이터 수집기

한국거래소 상장사(코스피 + 코스닥) **전체**를 대상으로 아래 4개 지표를
**2025년 1분기 ~ 2026년 2분기(반기)** 구간에 대해 수집·정리합니다.

| 지표 | 출처 | 비고 |
|---|---|---|
| 자산총액 | Open DART `fnlttMultiAcnt` (재무상태표 `자산총계`) | 분기말 잔액 |
| 매출액 | Open DART `fnlttMultiAcnt` (손익계산서 `매출액`/`영업수익`) | 누적·분기 단독 모두 산출 |
| 영업이익 | Open DART `fnlttMultiAcnt` (손익계산서 `영업이익`) | 누적·분기 단독 모두 산출 |
| 인력수 | Open DART `empSttus` (직원 등의 현황) | 사업·반기보고서 공시치 |

## ⚠️ 이 저장소에 데이터 파일이 없는 이유

이 세션의 이그레스(외부 접속) 정책이 `opendart.fss.or.kr`, `dart.fss.or.kr`,
`data.krx.co.kr` 로의 접속을 **403 으로 차단**하고 있어, 여기서는 실제 데이터를
받아올 수 없었습니다. 그래서 **키만 넣으면 바로 도는 수집 파이프라인**을 완성해
두었고, 산출물 형식은 `samples/` 에 실제와 동일한 컬럼 구성으로 넣어두었습니다.

사내에서 이 도메인을 허용하도록 이그레스 정책을 열어주시면 같은 코드로 이
환경에서도 바로 수집할 수 있습니다.

## 빠른 시작

```bash
pip install -r requirements.txt

cp .env.example .env
# .env 의 DART_API_KEY 에 https://opendart.fss.or.kr 에서 발급받은 인증키(40자) 입력

python run.py all --limit 20        # 20개사로 시험 실행 (5분 이내)
python run.py all                   # 전체 수집
```

산출물은 `data/out/` 에 생성됩니다.

| 파일 | 내용 |
|---|---|
| `kospi_kosdaq_quarterly.csv` | 기업 × 분기 tidy 테이블 (기본 산출물) |
| `kospi_kosdaq_quarterly.xlsx` | 위 데이터 + 지표별 시트 6개 |
| `pivot_total_assets.csv` 등 | 지표별 `기업 1행 × 분기 열` 피벗 6종 |
| `coverage.md` | 분기·시장별 데이터 확보율 리포트 |

형식 미리보기는 `samples/` 를 참고하세요 (가짜 데이터로 생성:
`python tools/make_sample.py`).

## 주요 옵션

```bash
python run.py all --markets kospi              # 코스피만
python run.py all --periods 2026Q1..2026Q2     # 최근 두 분기만
python run.py all --no-employees               # 인력수 생략 (호출 수 1/5로 감소)
python run.py all --emp-all-quarters           # 1·3분기도 직원현황 조회 시도
python run.py universe                         # 상장사 목록만 갱신
python run.py export                           # 캐시만 사용해 파일 재생성
python run.py all --rate 5 --workers 4         # 속도 조절
```

## API 호출량과 소요 시간

Open DART 인증키는 **하루 20,000건** 제한이 있습니다.

| 단계 | 호출 수 | 설명 |
|---|---:|---|
| `corpCode.xml` | 1 | 고유번호 전체 목록 |
| `company.json` | 약 2,700 | 시장구분(코스피/코스닥) 판별, 기업당 1회 |
| `fnlttMultiAcnt` | 약 170 | 100개사씩 묶어 조회, 6개 분기 |
| `empSttus` | 약 8,100 | 기업당 1회 × 인력 공시 분기 3개 |
| **합계** | **약 11,000** | 기본 8 req/s 기준 30~45분 |

모든 응답은 `data/cache/` 에 저장되므로 중단되거나 한도에 걸려도 다시 실행하면
**받아둔 구간은 건너뛰고 이어서** 수집합니다. 한도 초과 시 `[중단]` 메시지와 함께
종료 코드 3으로 끝나니, 다음 날 같은 명령을 그대로 다시 실행하면 됩니다.

## 데이터 처리 규칙

**연결 우선.** 응답에 연결(CFS)·별도(OFS)가 함께 오면 연결을 씁니다. 연결
재무제표를 작성하지 않는 회사는 별도로 대체하며, 어느 쪽을 썼는지는
`연결/별도` 컬럼에 남습니다.

**분기 실적 산출.** DART 는 손익 항목을 '당기 3개월'과 '당기 누적'으로 함께
주기도 하고 누적만 주기도 합니다. 다음 우선순위로 분기 단독 실적을 만들고,
근거를 `매출액(분기)산출근거` 컬럼에 기록합니다.

1. 1분기 → 누적이 곧 분기 실적 (`1분기=누적`)
2. 회사가 3개월 금액을 별도 제출 → 그 값 (`공시(3개월)`)
3. 그 외 → 당기 누적 − 직전 분기 누적 (`직전분기차감`, 사업보고서의 4분기가 여기 해당)

**계정명 편차 흡수.** 금융회사의 `영업수익`, 포괄손익계산서의 `수익(매출액)`,
`영업이익(손실)` 같은 표기 차이를 정규화해 같은 지표로 묶습니다.

**인력수.** '직원 등의 현황'은 사업보고서·반기보고서에만 실립니다(2019년 서식
간소화 이후 분기보고서는 대부분 생략). 따라서 1·3분기 행에는 직전 공시치를
이월하고 `인력수출처` 컬럼에 `2025Q2 공시치 이월` 처럼 표시합니다. 사업부문 ×
성별로 쪼개진 행의 합계(`sm`)를 더하되, 회사가 합계 행을 함께 제출한 경우
중복 합산되지 않도록 걸러냅니다.

## 알아두실 점

- **분기 라벨은 회계연도 기준입니다.** 12월 결산이 아닌 회사(3월·6월 결산 등)의
  `2025Q1` 은 달력상 1~3월이 아닙니다. 해당 기업은 `12월결산아님` 컬럼에 `Y` 로
  표시되니 필요하면 `결산월` 컬럼으로 보정해 쓰세요.
- **커버리지는 100%가 되지 않습니다.** 관리종목·감사의견 거절 등으로 보고서를
  제출하지 않은 회사, 신규 상장으로 과거 분기가 없는 회사, 결산기 변경 회사가
  있습니다. `coverage.md` 에서 분기·시장별 확보율을 확인하세요.
- **유니버스는 실행 시점 기준입니다.** 상장폐지된 회사는 빠지고 신규 상장사는
  들어옵니다. 특정 시점 기준으로 고정하려면 `data/cache/universe.csv` 를 보관해
  두었다가 재사용하세요.
- **통화 단위.** 대부분 원(KRW)이지만 일부 회사는 다른 통화로 공시합니다.
  `통화` 컬럼을 확인하세요.

## 구조

```
run.py                  CLI 진입점
krfin/
  config.py             설정 (.env 로딩 포함)
  periods.py            분기 정의 · 보고서 코드 매핑
  dart.py               Open DART 클라이언트 (속도 제한 · 재시도 · 디스크 캐시 · 한도 추적)
  corps.py              corpCode.xml + company.json → 코스피/코스닥 유니버스
  financials.py         fnlttMultiAcnt → 자산총계 · 매출액 · 영업이익
  employees.py          empSttus → 인력수
  assemble.py           기업 × 분기 레코드 결합 · 분기 실적 산출
  export.py             CSV · 피벗 · 엑셀 · 커버리지 리포트
tools/make_sample.py    가짜 응답으로 산출물 형식 예시 생성
tests/                  네트워크 없이 도는 검증 (19개)
```
